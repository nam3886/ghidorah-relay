## Workflow

Team work uses the superpowers plugin as shipped. This folder is the relay repo on `main` (the owner's); task worktrees live in `.worktrees/<slug>`. Tests run on the box (`phuongnam@192.168.18.227`) through `scripts/box.sh` and `scripts/web.sh`, always with `--tree <the worktree's folder name>`. Up to 3 narrow runs (test files, mutation of chosen markers, browser files) may run at once, each pinned to its own third of the cores: `env RELAY_GATE_CPUS=0-7`, `8-15` or `16-23` (24-31 stay for production). Before starting, take a set that no running run uses: `ssh phuongnam@192.168.18.227 'for c in $(docker ps -q --filter name=relay-check-run); do docker inspect -f "{{.HostConfig.CpusetCpus}}" $c; done'`; wait when all three are taken. `RELAY_GATE_CPUS` goes in front of `scripts/box.sh` on the Mac, never inside the `--` command; each agent keeps to one run at a time. A whole-tree gate (`check.sh --full`, or `check.sh` with no test path) runs alone with `RELAY_GATE_CPUS=0-23`: shared cores make tests fail falsely.

1. A subagent that changes code is spawned with the Agent tool's `isolation: "worktree"` (Claude Code makes `.claude/worktrees/agent-<id>` on branch `worktree-agent-<id>`); no worktree is made by hand. Its prompt says: check the base with `git log -1` and `git reset --hard <sha>` when it is wrong; edit and commit only in that worktree, never the main worktree or its index; run the tier's checks before reporting done. Its diff (`git -C <worktree> diff <base> HEAD`) is applied unstaged to the main worktree with `git apply` for the owner's review, and committed only when the owner says so; then `git worktree remove <path>` and `git branch -D worktree-agent-<id>`.
2. The checks match the task's tier. Propose the tier when the task starts; the owner may change it.
   - **S**: admin web UI only (`apps/admin-web/src/**` and its tests), no API contract change. Before hand-over: `scripts/web.sh check`, then `scripts/web.sh build` (the browser tests run the built bundle: without a build they test the old UI), then `scripts/box.sh -- scripts/check-in-container.sh <browser test files of the changed page> [-k <page>]` (it refuses a stale bundle; while iterating, `scripts/web.sh test <spec files>` runs only those Vitest specs); fix every test or marker anchor the change breaks. The owner reviews 1–2 before/after screenshots in chat. No plan file, no reviewer subagent.
   - **M**: backend or admin API that does not touch money, the database schema, auth, secrets or the provider send path. S, plus `scripts/box.sh -- scripts/check.sh <changed test files and the tests of the changed modules>` and one reviewer subagent.
   - **L**: money (charge, refund, budget, points), migrations, auth, secrets, the dola submit/recover path, deploy files. M, plus full pytest, the mutation run of every marker file naming a changed source file, and a Codex review. Deploy only after a full gate that contains the commit is `CHECK: GREEN`.
3. The full gate (`scripts/check.sh --full`, about 4 h) runs on `main`, not before every hand-over: nightly once automated, until then started by the manager after the day's merges (`scripts/box.sh --detach gate-main -- scripts/check.sh --full`). A red gate is fixed the next day; a real regression on production is rolled back first.
4. Before every commit: the secret scan (counts only). Commit messages carry no AI reference and no Co-Authored-By line. The owner approves each merge to `main` and each deploy; for tier S a "ok" on the screenshots is that approval.
