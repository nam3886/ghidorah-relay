## Workflow

Team work uses the superpowers plugin as shipped. This folder is the relay repo on `main` (the owner's); task worktrees live in `.worktrees/<slug>`. Tests run on the box (`phuongnam@192.168.18.227`) through `scripts/box.sh` and `scripts/web.sh`, always with `env RELAY_GATE_CPUS=0-23` and `--tree <the worktree's folder name>`. Run one heavy box job at a time: parallel runs overload the box and make tests fail falsely.

1. Every task gets its own worktree from `main` (`git worktree add .worktrees/<slug> -b <slug> main`); a subagent edits and commits only there and never touches the root or another worktree.
2. The checks match the task's tier. Propose the tier when the task starts; the owner may change it.
   - **S**: admin web UI only (`apps/admin-web/src/**` and its tests), no API contract change. Before hand-over: `scripts/web.sh check` and `scripts/box.sh -- scripts/check-in-container.sh <browser test files of the changed page>`; fix every test or marker anchor the change breaks. The owner reviews 1–2 before/after screenshots in chat. No plan file, no reviewer subagent.
   - **M**: backend or admin API that does not touch money, the database schema, auth, secrets or the provider send path. S, plus `scripts/box.sh -- scripts/check.sh <changed test files and the tests of the changed modules>` and one reviewer subagent.
   - **L**: money (charge, refund, budget, points), migrations, auth, secrets, the dola submit/recover path, deploy files. M, plus full pytest, the mutation run of every marker file naming a changed source file, and a Codex review. Deploy only after a full gate that contains the commit is `CHECK: GREEN`.
3. The full gate (`scripts/check.sh --full`, about 4 h) runs on `main`, not before every hand-over: nightly once automated, until then started by the manager after the day's merges (`scripts/box.sh --detach gate-main -- scripts/check.sh --full`). A red gate is fixed the next day; a real regression on production is rolled back first.
4. Before every commit: the secret scan (counts only). Commit messages carry no AI reference and no Co-Authored-By line. The owner approves each merge to `main` and each deploy; for tier S a "ok" on the screenshots is that approval.
